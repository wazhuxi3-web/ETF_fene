# 深交所 ETF PCF 采集设计

## 目标

在现有 ETF 份额与成分股工具中增加深交所 ETF 申购赎回清单（PCF）采集能力，同时支持“当前日更新”和“按日期区间补历史”。采集使用后台隐藏浏览器模拟深交所网页操作，避免直接高频调用接口触发反爬。数据继续写入现有 `ETF_INFO` 和 `ETF_ITEM`，不新增业务列，通过 `交易所 = SZSE` 与上交所数据区分。

## 官方数据源

- 用户提供的 `https://www.szse.cn/market/trend/index.html?code=159001` 是行情信息页，不是 PCF 页面。
- PCF 页面固定为 `https://www.szse.cn/disclosure/fund/currency/index.html`。
- 页面报表编号为 `sgshqd`，支持代码或简称、开始日期和结束日期查询；页面单次查询范围上限为一年。
- 查询结果链接到深交所 PCF 下载页。下载页会依次寻找 `pcf_代码_日期` 和 `代码ETF日期` 两种文件名的 TXT/XML 文件。
- 当前文件主要为 `PCFFile` XML；历史文件可能为 TXT，因此采集器必须同时支持 XML 和历史 TXT。
- 已验证 `159001` 的 `2024-09-20` 历史 PCF 仍可查询，`159915` 当前 XML 能返回完整成分列表。

## 功能范围

GUI 的 PCF 区域改名为“ETF成分股（PCF）”，保留现有上交所功能并新增：

- `采集深交所当前 PCF`：代码为空时采集当前公告日全部深交所 ETF；填写六位代码时只采该 ETF。
- `采集深交所历史 PCF`：使用现有开始日期和结束日期；代码为空时补全部 ETF，填写代码时只补该 ETF。
- `重新采集已有快照`复选框：默认关闭。关闭时完整快照直接跳过；开启时重新下载并原子替换相同基金、相同日期的快照。

“当前 PCF”先查询当天；当天没有结果时，回退到 `stock_daily` 中不晚于当天的最近交易日。“历史 PCF”从 `stock_daily` 读取区间内去重后的真实交易日，不请求周末和休市日。GUI 日期区间不限制为一年，因为程序按单个交易日逐日操作页面。

## 数据模型

不改变 `ETF_INFO`、`ETF_ITEM` 的业务列和唯一键。

```text
ETF_INFO: 交易所 + 基金代码 + 内容日期
ETF_ITEM: 交易所 + 基金代码 + 内容日期 + 证券代码 + 挂牌市场
```

```text
交易所                                      = SZSE
基金代码                                    = SecurityID
基金名称                                    = Symbol
基金管理公司名称                            = FundManagementCompany
最新公告日期                                = TradingDay
内容日期                                    = TradingDay
现金差额                                    = CashComponent
最小申购、赎回单位净值                      = NAVperCU
基金份额净值                                = NAV
最小申购、赎回单位的预估现金部分            = EstimateCashComponent
现金替代比例上限                            = MaxCashRatio
当日累计可申购的基金份额上限                = CreationLimit
当日累计可赎回的基金份额上限                = RedemptionLimit
当日净申购的基金份额上限                    = NetCreationLimit
当日净赎回的基金份额上限                    = NetRedemptionLimit
单个证券账户当日累计可申购的基金份额上限    = CreationLimitPerUser
单个证券账户当日累计可赎回的基金份额上限    = RedemptionLimitPerUser
单个证券账户当日净申购的基金份额上限        = NetCreationLimitPerUser

```

深交所 XML 中没有现有列对应的字段不保存，不通过新增列扩展数据库。

### ETF_ITEM 映射

```text
交易所                          = SZSE
基金代码                        = SecurityID
内容日期                        = TradingDay
证券代码                        = UnderlyingSecurityID
证券简称                        = UnderlyingSymbol
股票数量                        = ComponentShare
现金替代标志                    = SubstituteFlag 原始值
申购现金替代溢价比例            = PremiumRatio
赎回现金替代折价比例            = DiscountRatio
挂牌市场                        = UnderlyingSecurityIDSource：101 -> SSE，102 -> SZSE，未知值保留原值
```

深交所有 `CreationCashSubstitute` 和 `RedemptionCashSubstitute` 两个金额，而现有表只有“替代金额”，按用户确认的规则统一：

1. 两个金额相同，写入该金额。
2. 只有一个金额非零，写入非零金额。
3. 两个金额均非零且不同，写入申购现金替代金额，并在当次采集汇总日志中统计此类记录数量。

金额单位保存为元，股票数量保存为股，基金份额保存为份，比例保留官方文件原始数值；列名不带单位。`source` 保存 `szse_pcf_browser`。

## 浏览器采集流程

1. 启动一个 Playwright Chromium 后台浏览器，固定 `headless=True`，不显示窗口、不抢焦点。
2. 打开深交所 PCF 页面并等待报表查询控件出现。
3. 填写代码（可空）、开始日期和结束日期；每次只查询一个交易日。
4. 点击查询，通过页面分页取得当天全部 PCF 结果和官方下载页参数。
5. 对每条结果先调用数据库完整性检查；默认跳过已有完整快照。
6. 使用同一浏览器会话访问结果中的官方下载页，由页面自身探测 `pcf_代码_日期.txt`、`pcf_代码_日期.xml`、`代码ETF日期.txt`、`代码ETF日期.xml` 四种候选文件并打开实际存在的文件。
7. 每个文件之间随机等待 0.8 至 1.8 秒，不使用多线程下载。
8. 单个文件失败最多重试三次，退避间隔依次为 2、5、10 秒。
9. 解析完成且基金代码、内容日期和至少一条成分记录有效后才允许写入数据库。
10. 每只基金完成后立即提交快照，使程序意外退出后能够根据数据库继续跳过已完成基金。

当前日全量与历史区间共用同一采集器。历史采集逐交易日执行，不把不同日期混成一次大下载，也不使用深交所份额采集的 5 个月/15 天切段规则。

## 快照写入

新增数据库方法按一只基金、一个内容日期原子写入：

1. 开启事务。
2. 校验 `ETF_INFO` 和全部 `ETF_ITEM` 的交易所、基金代码、内容日期一致。
3. 删除相同 `交易所 + 基金代码 + 内容日期` 的旧 `ETF_ITEM`。
4. 幂等写入一条 `ETF_INFO`。
5. 插入本次解析出的全部 `ETF_ITEM`。
6. 全部成功后提交；任一步失败则回滚，原快照保持不变。

默认模式下，`ETF_INFO` 存在且 `ETF_ITEM` 至少一行即视为已有完整快照并跳过下载。勾选“重新采集已有快照”时执行上述替换流程，因此同一天新增或剔除成分都能准确反映，历史日期记录不受影响。

## 暂停、续采与日志

- 单个 PCF 文件下载或解析失败：记录基金代码和日期，继续同一天其他基金。
- 页面查询、浏览器进程或网络整体失败：暂停在当前交易日，不自动跳到下一日。
- `测试连通性/继续采集` 对暂停的深交所 PCF 任务执行真实页面查询和一个小文件读取；成功后从暂停日期继续。
- 程序退出后再次选择同一区间，依靠完整快照检查自动跳过已经完成的数据。
- 日志按日期汇总，不为每个成功文件刷一行；失败文件单独列出。

日志示例：

```text
[采集] 深交所 2026-07-14：发现 695 只，已有 680 只，待采集 15 只。
[入库] 深交所 2026-07-14：成功 14 只，失败 1 只，写入成分 1,436 行。
[提示] 2 条成分的申购、赎回替代金额不同，已按申购金额保存。
```

## 测试与验收

- XML 解析覆盖普通股票 ETF、货币 ETF 虚拟证券 `159900`、缺失可选字段和 XML 命名空间。
- 历史 TXT 解析覆盖参数区、成分区和不同文件编码。
- 四种官方下载文件名均能被识别，浏览器最终打开的实际文件能够交给对应解析器。
- 替代金额三条映射规则均有独立测试。
- `101 -> SSE`、`102 -> SZSE` 和未知代码来源映射正确。
- `stock_daily` 只返回区间内真实交易日；当前日无数据时回退最近交易日。
- 默认跳过已有完整快照；强制重采能够删除被剔除成分并保留其他历史日期。
- 文件解析失败、空成分或数据库写入失败不会破坏原快照。
- 浏览器固定隐藏、单线程，下载间隔和三次退避重试可测试。
- GUI 包含当前日、历史区间、可选基金代码和重新采集开关；日志区仍独立滚动。
- 运行全部现有测试，确认上交所 PCF、沪深份额采集和网页曲线无回归。
- 联网验收先采一只 `159915`，核对一条 `ETF_INFO` 和 100 条左右 `ETF_ITEM`；再采一个交易日全量并核对成功、跳过、失败统计。

## 不在本次范围

- 不为 PCF 增加网页端成分股展示页面。
- 不并发下载深交所 PCF。
- 不补充深交所专有数据库字段。
- 不把指数成分股、基金季报持仓当作每日 PCF。
